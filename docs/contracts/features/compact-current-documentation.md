# Компактная документация текущего поведения

Статус: APPROVED. Оператор явно согласовал отдельный документационный PR: README и все Markdown-файлы, сокращение процессных контрактов без изменения правил, удаление устаревшего контракта ручного compact.

## Цель и сценарии

Каждая страница читается за 1–2 минуты: назначение → действие → результат → ограничения. Ориентир — 250–450 слов, предпочтительно до 400 технических русских слов. Читаемость, включая плотные таблицы, оценивает человек; счётчик и однострочное сжатие её не заменяют.

- Новичок понимает назначение проекта и находит безопасный первый шаг.
- Оператор находит запуск, команды, результаты, ошибки и действия при разрыве связи.
- Разработчик находит нормативную границу, гарантии и обязательный процесс без изучения истории.

Разделять страницы только по вопросам читателя или границам справочника. Mermaid обязателен там, где яснее: кандидаты — архитектура и локальное/Native владение, публичный lifecycle, порядок written/control/result/SSE. Схемы основаны на исходниках, не изображают списки и не выдумывают ACK, completion, idle или завершение всех background tasks.

## Интерфейсы, ограничения и нецели

Только документация: поведение, API, зависимости, исходники, тесты, package/lock, CI и скрипты неизменны. Установка, service rollout, private config/auth, SSH/env-файлы и install paths не затрагиваются. Native-бюджет исчерпан: запрещены Native/SDK/model/CLI warmups, реальные примеры и установки; разрешены Node fake-проверки и безопасные локальные проверки синтаксиса.

Гарантии, ошибки, security/privacy, владение Native, lifecycle, validation/platform limits, approval/process/CI/merge rules сохраняются без ослабления и пропусков. Допустима ссылка на единственный полный справочник. При переписывании метаконтракта действуют исходные процессные правила.

Убираются итерационная история, старые бюджеты/счётчики тестов, удалённые возможности, архивные commit/git-show ссылки и приватные пути. Актуальные compatibility/source links и необходимые ограничения остаются. Token не попадает в argv/env/URL/log; приватные факты и nonce не публикуются.

## Приёмка и проверка

До переписывания прочитать все 24 `src/*.ts` и релевантные тесты; составить source-grounded план. Проверить полное покрытие исходных гарантий, ссылки, примеры и схемы. Linux fake/typecheck и Windows fake smoke не означают full-suite Windows или Native Windows certification. Реальный Linux smoke ограничен базовым двухходовым сценарием Sonnet 5.5; tools, permissions, compaction и persistence им не сертифицированы.

Обязательны независимое review, repo-docs `scripts/check_docs.py` для всего репозитория, `node --test test/surface-docs.test.ts`, релевантные Node fake-тесты и typecheck. Проверить Mermaid доступным renderer без новых зависимостей; иначе выполнить ручную проверку и checker, явно указав, что полный render не запускался.
