# Стабильная доставка событий

Статус: approved; активен до независимого ревью и приёмки родителя.

## Цель
Стабильная и причинно упорядоченная доставка событий существующего core без архитектурной переработки.
Затрагиваемая поверхность: [ядро сессий](../surfaces/session-core.md).

## Сценарии
- Каждая публикация session/input/text фиксирует набор подписчиков в момент publish; каждому событие доставляется не более одного раза.
- Self-resubscribe, добавление и удаление слушателей влияют только на последующие публикации. Отписка после фиксации не отменяет текущую или поставленную доставку.
- Вложенные синхронные публикации, включая межтиповые и межсессионные, доставляются FIFO после доставки внешнего события всем его получателям.
- Несколько observers не должны получать старый pending после нового completed вследствие reentry другого observer.
- Синхронные исключения и отклонения Promise слушателей изолируются; асинхронное завершение не ожидается.

## Интерфейсы и ограничения
Публичные интерфейсы неизменны; сохраняются все session/input/lifecycle/privacy гарантии поверхности.
Очередь существует только для текущей доставки: это не история, replay, ревизии или DTO snapshots.
Нет гарантии sandbox или защиты от callback, который не возвращается либо бесконечно порождает события.
Не более четырёх production core/interface файлов; каждый авторский файл не более 100 строк.
Без новых движков, иерархий, forwarding, frameworks, dependencies и codegolf; при нехватке бюджета требуется согласование.

## Нецели
Другие P2, toolchain/package/README, runtime/API/native adapters/SDK/persistence/settings/model loop/quotas.
Без network jobs, dependency install, remote push/PR/merge/deployment/restarts и adjacent/global изменений.
Существующий node_modules donor не изменять.

## Приёмка
Регрессии покрывают все три типа событий; self-resubscribe/add/remove/новых получателей/следующую публикацию;
snapshot при enqueue; FIFO с двумя и более observers и несколькими вложенными/межтиповыми событиями;
reentry и error isolation. Старые гарантии и тесты сохранены. Изменения ограничены delivery seam.
Durable surface не менять, feature не финализировать до независимой приёмки.

## Валидация
Новые class-wide регрессии, все старые tests, npm run typecheck, npm test, git diff --check,
проверка docs через repo-docs/scripts/check_docs.py; проверить бюджет файлов и неизменность donor.
Контракт фиксируется отдельным локальным коммитом до планирования и реализации; проверенный implementation/test increment — отдельным коммитом.
